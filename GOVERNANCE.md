# Project Governance

Fabric Reference Node uses **evidence-first maintainer governance**.

## Principles

1. Public APIs and schemas change through reviewable commits.
2. New claims about capability require reproducible evidence.
3. Machine execution never silently promotes scientific, formal, legal, security, or institutional authority.
4. Backwards-incompatible semantic changes require a versioned migration note.
5. Security fixes may be embargoed until coordinated disclosure is safe.
6. Funding does not purchase validation or reviewer authority.

## Maintainer model

The project begins with a founder-maintainer model. The roadmap includes expanding maintainership after sustained external contributions and review history exist.

## Decision records

Non-trivial semantic decisions should be recorded under `docs/decisions/` as short Architecture Decision Records (ADRs).
